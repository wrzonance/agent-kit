# agent-kit

## North star

agent-kit makes agent workflows **fast, cheap, and quiet**. Judge every change by that:

- **Few turns, few tokens.** Fewer root turns and tool calls, tool output that hands the agent
  exactly what it needs, less back-and-forth with the operator.
- **Scoped sub-agents.** Each worker owns one isolated worktree: it does the job, commits,
  pushes, and ends. The root organizes and reviews.
- **The invocation is the authorization.** Flags and the operator's own words already grant what
  they name; ask the operator only for decisions they have not made yet.
- **Guard against untrusted input** (issue bodies, fetched content, cross-provider sends); trust
  the operator who chose to run the kit.
- **No run started, no blocker.** State left by an old or absent run never stops ad-hoc work.

Before adding any rule, gate, check, flag, or step, answer: **which measured turn, token, or
failure does it remove?** Name it in the PR. When you can't, make the change smaller; removing
ceremony is usually the better fix.

## Commands

```bash
tests/run-tests.sh                         # canonical local gate; CI runs the same script
tests/run-tests.sh --only finding-ledger   # one suite (name without test-/.sh), gates included
bash tests/test-finding-ledger.sh          # one suite alone, fastest red/green loop
tests/run-tests.sh --gates-only            # static gates only
tests/build-plugin.sh                      # regenerate plugin/ from agentkit/
shellcheck -x -P SCRIPTDIR -S style <script>   # pinned ShellCheck 0.11.0
```

## Where things live

- `agentkit/` ships to every user repository: `skills/<skill>/SKILL.md` with `references/` and
  `scripts/`, shared helpers in `skills/.shared/scripts/`, and lifecycle hooks in `hooks/`.
- `plugin/` is generated by `tests/build-plugin.sh`; edit `agentkit/` instead.
- `tests/test-*.sh` are the suites (helpers in `tests/lib/assert.sh`); `tests/lint-*.sh` are gates.
- `bench/` is the token benchmark; CI's `[skip ci]` tier0 commits on `main` are expected.
- Plans live in `docs/superpowers/plans/`; release steps in `RELEASING.md`.

## Rules the gates enforce

- **Stay general.** Shipped skills must work on Codex and Claude and in any repository; the
  harness/environment/org/ecosystem-neutrality gates check this. Keep behavior specific to this
  repository in `tests/`, `.github/`, `RELEASING.md`, or `.agent/`.
- **Size ratchets** (`tests/lint-skill-size.sh`, `tests/lint-helper-size.sh`): a deliberate
  growth raises the ceiling in the same change with a comment naming the issue and reason.
- **Shell:** bash 5.2, `set -euo pipefail`; pin `LC_ALL=C` on every `sort`/`comm`; skills call
  helpers through the resolved `"$agentkit/..."` form, never a version-pinned plugin path.
- **Release gate:** shipped bytes may change only under an untagged version. After tagging a
  release, run `tests/prepare-next-version.sh VERSION` so `main` moves to the next patch.

## Writing helpers and tests

- A helper does one job in one call and prints only what the caller needs next. Refusals name
  the cause and the command that fixes it: `die_usage` exits 2 for bad input, evidence failures
  exit 1.
- A helper that enforces a rule beats prose asking an agent to remember it. Cut prose only while
  the pinned tests show agents still follow it.
- Suites follow the existing shape: set `TEST_NAME`, source `tests/lib/assert.sh`, build fixtures
  in `mktemp -d`, assert with `assert_eq`/`assert_contains`/`assert_not_contains`/`assert_rc`,
  and end with `finish`. Pin every bugfix with a test that fails before the fix.

## Working here

- The repository root is the operator's checkout. Agents work in `.worktrees/<branch>` on a
  `type/slug` branch from `origin/main`; run suites from the checkout, not a copy under `/tmp`.
- PRs open as drafts and carry one demonstrable change; the operator marks them ready, merges,
  and triggers review bots.
- Commits use Conventional Commits and credit the agent that did the work with a
  `Co-Authored-By` trailer.
