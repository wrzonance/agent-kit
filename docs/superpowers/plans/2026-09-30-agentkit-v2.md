# agentkit v2 implementation plan

Spec: `docs/superpowers/specs/2026-09-30-agentkit-v2-design.md`. Branch: `feat/ak-v2` (built on the spec branch).

## Task 0: decisions pinned before code

- **Config.** Read the existing `.agent/config.env` (`KEY=value` lines, parsed, never sourced or eval'd). The keys
  already exist in onboarded repos, so there is no re-onboarding:
  - `AGENT_REPO_SLUG`, `AGENT_BASE_BRANCH`, `AGENT_WORKTREE_ROOT`;
  - `AGENT_PROJECT_OWNER`, `AGENT_PROJECT_NUMBER`;
  - `AGENT_PROTECTED_PATHS`;
  - `AGENT_WORKER_MODELS`, `AGENT_WORKER_EFFORT`;
  - `AGENT_CMD_SETUP`, `AGENT_CMD_VERIFY`, `AGENT_CMD_TEST`, `AGENT_CMD_<NAME>` + `AGENT_RUNDIR_<NAME>`;
  - `AGENT_ADVERSARIAL_REVIEWER`, `AGENT_ADVERSARIAL_REVIEW_MODEL`, `AGENT_ADVERSARIAL_REVIEW_EFFORT`.

  Missing keys fall back to defaults or to what git can tell us: the slug from the `origin` remote, the base from
  `origin/HEAD`.
- **Harness.** Same detection as v1 `harness-id.sh`: env `CLAUDECODE`/`CLAUDE_CODE_ENTRYPOINT` → claude, `CODEX_*`
  → codex. It determines the commit trailer and the other-provider reviewer.
- **Paths.** Each SKILL.md tells the model to run `<skill dir>/../../bin/ak`. Both harnesses show the skill's
  directory, so no resolver or preflight is needed.
- **State.** Written only under `<worktree>/.ak/` and `<repo root>/.ak/runs/`. `ak` adds `.ak/` to
  `.git/info/exclude` on first use.
- **GitHub.** REST via `gh api` everywhere, except the Projects v2 board: `gh project item-list/item-edit`.

## Task 1: skeleton and gates

These are the files every later task builds on.

- `v2/bin/ak`: a dispatcher. `ak <cmd> args…` sources `v2/lib/<cmd>.sh` and calls `cmd_main "$@"`. With no
  arguments it prints the usage.
- `v2/lib/common.sh`, the shared helpers:
  - `die` (one cause line plus one fix line, exit 1);
  - `usage_die` (exit 2);
  - `cfg KEY [default]`;
  - `repo_root`, `harness`, `trailer`, `slug`, `base`;
  - `run_logged` (runs a command, tees to `.ak/logs/`, prints only a PASS/FAIL line plus the tail on failure).
- Manifests:
  - `v2/.codex-plugin/plugin.json` and `v2/.claude-plugin/plugin.json` (name `ak`, version 0.1.0, skills
    `./skills/`, no hooks);
  - a marketplace entry `{"name":"ak","source":"./v2"}`.
- Tests:
  - `tests/v2/lib.sh`: a fake `gh` and a fixture repo with an origin remote;
  - `tests/v2/test-common.sh`.
- Gates, in `tests/v2/lint-budget.sh`:
  - each SKILL.md ≤ 120 lines;
  - `v2/**/*.md` ≤ 40 KB;
  - `v2/bin` + `v2/lib` ≤ 5,000 lines;
  - no `hooks` key in the manifests;
  - shellcheck on everything.

  Wire them into `tests/run-tests.sh` and extend the neutrality gates to `v2/`.

## Task 2 (parallel): `ak plan`, `ak collect`, skill `issues`

- **`plan`**
  1. Read the board (Ready, plus Backlog with `--yolo`) with `gh project item-list`.
  2. Filter:
     - open issues only;
     - exclusion labels (`AGENT_EXCLUDE_LABELS`, default `tier:human-only,needs:brainstorm,blocked`);
     - open `blocked_by` dependencies, via REST.
  3. Write sets are path tokens from the body that exist in `git ls-files` (or name an existing directory for a new
     file). A protected-path hit drops the issue. Overlap between two sets defers the later issue, or chains it
     with `--serialize`.
  4. For each chosen issue (up to `--limit`, default 3):
     - create a worktree `feat/issue-N` from `origin/base` and push it upstream;
     - write `.ak/issue.md` (fenced, untrusted);
     - write `.ak/prompt.md` from `v2/templates/issue-worker.md`;
     - move the board item to In progress.
  5. Record the root checkout's `git status --porcelain` in the run file.
  6. Print the `spawn`/`after`/`drop` lines from the spec.
- **`collect --issue N`**
  1. Read `.ak/result`.
  2. Compare the root porcelain with the run file (report `cross-write=` only on a difference).
  3. Mark the issue collected.
  4. For `after` successors whose needs are all collected: create the worktree from the predecessor's pushed branch
     and print `spawn` lines.
  5. Print the `pr=… ci=… review=… note=…` line.
- **`v2/skills/issues/SKILL.md`**: the five root steps from the spec. That's the whole file.

## Task 3 (parallel): the worker commands

- **`setup`**: runs `AGENT_CMD_SETUP` once (stamp `.ak/setup.ok`).
- **`verify`**
  - Runs `AGENT_CMD_VERIFY`, or `AGENT_CMD_TEST` when there's no verify, then every `AGENT_CMD_<NAME>` whose
    `AGENT_RUNDIR_<NAME>` holds a changed path.
  - Prints `verify=pass|fail`, the failing command's tail, and `skipped=<names>` taken from any `SKIP …` output
    lines.
  - When anything was skipped, it prints `oracle=ci` (the worker must get `ak ci` green before claiming done).
- **`ship --message M [--body-file F]`**
  1. `git add -A` (`.ak/` excluded), then commit with the harness trailer.
  2. `git push`.
  3. Open the draft PR if none exists: title from the issue, body = banner + Why/What from `F` + `Closes #N` +
     attribution.
  4. Move the board item to In review.
  5. Print `pr=URL head=SHA`.
- **`ci [--timeout 1800]`**
  - Polls REST check-runs for the head every 30 s until nothing is pending.
  - On failure: fetch each failing job's log (`gh api --allow-escape-sequences`), strip ANSI, save it to `.ak/ci/`,
    print the check name plus up to 8 error lines each. At most 20 lines in total.
- **`receipt --findings F`**
  - Posts one PR comment: banner, reviewed SHA, reviewer model, one line per finding (`P1 | title | fixed <sha>` or
    `declined: reason`), and CI state.
  - Writes `.ak/result`.
- **`v2/templates/issue-worker.md`**: the worker playbook (spec steps 1-8), with the issue block and commands
  inlined.

## Task 4 (parallel): review, PR workers, merge, skill `pr`

- **`review`**
  1. Build the diff `origin/base...HEAD`.
  2. Run the other provider, blind:
     - under Codex, reviewer claude: `claude --print --model <m> --tools "" --permission-mode dontAsk`;
     - under Claude, reviewer codex: `codex exec --ephemeral --skip-git-repo-check -s read-only -m <m> -c
       model_reasoning_effort=<e> -o OUT -`.

     The prompt is the header plus the diff, and the model comes from config.
  3. Timeout of 20 min. Write `.ak/review.md` and print `findings=N` plus one line per finding title with its
     severity. When the reviewer is unavailable, print `review=unavailable reason=…` and exit 0. That's evidence,
     not a blocker.
- **`pr-plan --pr N…`**: for each PR, create or reuse the worktree for its head branch, write `.ak/prompt.md` from
  `v2/templates/pr-worker.md` (steps 4-8), and print `spawn` lines.
- **`merge --pr N`**: requires `ak ci --once` green on the head, then marks the PR ready and squash-merges it via
  REST. The branch is deleted only when no open PR uses it as a base.
- **`v2/skills/pr/SKILL.md`**: `ak pr-plan`, spawn, wait, `ak collect --pr N`, `ak merge` when the invocation says
  `--merge`.

## Task 5: integrate

Merge the three branches into `feat/ak-v2`, run the full `tests/run-tests.sh` and the budget gate, then open a
draft PR.

## Task 6: field run (operator)

1. Install on jacobs: `codex plugin add ak@agent-kit`, then restart the app-server.
2. Run cable-tool: `$ak:issues --yolo --limit 2`.
3. Measure against the spec's budget table and ledger every miss.

## Task 7: delete v1

Only after Task 6 meets the budgets.
